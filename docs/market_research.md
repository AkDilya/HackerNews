# Анализ рынка и конкурентов (Market Research) для TrendRadar

## 1. Введение
Проект **TrendRadar** — это система поддержки принятия решений (DSS), которая агрегирует данные из IT-сообществ, анализирует их с помощью AI и визуализирует тренды. Для понимания места нашего продукта на рынке был проведен анализ существующих решений, работающих с открытыми API (Hacker News, Dev.to, GitHub).

## 2. Анализ аналогов и работы с API

### 2.1. Экосистема Hacker News API
Hacker News API является полностью открытым (без ключей и строгих лимитов), что породило множество сторонних инструментов:
*   **SDK и клиенты (например, `hn-api-client`):** Библиотеки для разработчиков, которые автоматизируют рутину — батчинг запросов (загрузка пачки статей одним запросом), обработку ошибок и real-time обновления. 
    *   *Их фишка:* Скорость и удобство для разработчиков.
*   **Специализированные агрегаторы (например, HNHIRING.com):** Сервисы, которые вычленяют из общего потока только посты из тредов «Who is Hiring».
    *   *Их фишка:* Узкая специализация и решение конкретной боли (поиск работы).
*   **MCP-серверы (для AI-агентов):** Инструменты, которые превращают HN в источник данных для LLM (Claude, Cursor). 
    *   *Их фишка:* Предоставление данных в формате, понятном нейросетям (инструменты «получить тред», «найти пользователя»).

### 2.2. Работа с другими открытыми API
*   **Dev.to API:** Предоставляет доступ к статьям разработчиков. 
    *   *Их фишка:* Прозрачные лимиты (3 запроса в секунду, 30 в минуту) и наличие SDK с автоматическим троттлингом (замедлением), чтобы не превышать лимиты.
*   **GitHub API:** Используется для аналитики Open-Source.
    *   *Их фишка:* Использование **условных запросов (Conditional Requests)** через заголовки `ETag`. Если данные не изменились, сервер отвечает `304 Not Modified`, и этот запрос не тратит лимит (что критически важно для систем, опрашивающих репозитории каждые 5 минут).

## 3. Уникальное торговое предложение (УТП) TrendRadar
В отличие от существующих решений, TrendRadar не просто собирает данные или фильтрует их по ключевым словам. Наши ключевые отличия:

1.  **Глубокая аналитика, а не просто список:** Мы не просто показываем статьи, мы строим **интерактивный граф связей** (какие технологии обсуждают вместе) и анализируем **тональность** (позитив/негатив).
2.  **Приватность и Zero-Cost AI:** Использование локальной LLM (Ollama) для генерации саммари статей. Это обеспечивает безопасность данных (ничего не уходит в облака) и нулевую стоимость (в отличие от OpenAI).
3.  **Мультиисточниковый сбор:** Мы агрегируем данные из двух платформ (Hacker News и Dev.to), что дает более полную картину трендов, чем анализ одной платформы.
4.  **Персонализация:** Система «Избранного» и «Умная лента» адаптируют дашборд под интересы конкретного пользователя.

## 4. Выводы и рекомендации для развития
На основе анализа конкурентов и их работы с API, можно выделить следующие направления для развития проекта:
1.  **Внедрение условных запросов (ETag):** Если мы добавим GitHub API в будущем, нам стоит использовать `ETag`, чтобы не тратить лимиты запросов впустую (как это делают топовые аналитические сервисы).
2.  **Поиск по комментариям (Algolia HN Search):** Сейчас мы ищем по заголовкам. Использование Algolia API (как в MCP-серверах) позволит находить обсуждения технологий даже там, где их нет в заголовке.
3.  **Событийные уведомления (Event Stream):** Вместо простого дашборда, можно перенять опыт Pipedream и сделать «детектор аномалий», который отправляет уведомление в Telegram, если технология резко набирает популярность.
