# ДЗ №1. Выбор AI-инструментов для проекта TrendRadar

**Проект:** TrendRadar — трекер технологических трендов на основе Hacker News  
**Стек:** React 18 + Vite, FastAPI, MongoDB, APScheduler, Ollama  
**Формат работы:** локальная разработка на Windows, бюджет проекта — 0 ₽

---

## 1. Анализ требований проекта

### 1.1. Краткое описание TrendRadar

TrendRadar собирает свежие статьи с Hacker News, анализирует заголовки с помощью LLM, извлекает технологии, тональность и категорию, сохраняет результаты в MongoDB и визуализирует их в веб-интерфейсе.

Основные части системы:

- **backend/** — FastAPI-приложение с асинхронным доступом к MongoDB через Motor. Реализует REST API для трендов, графа технологий, избранного и авторизации.
- **collector/** — отдельный воркер: загружает top stories через `httpx`, анализирует их через Ollama и APScheduler, сохраняет данные напрямую в MongoDB.
- **frontend/** — SPA на React 18 и Vite: дашборд, проводник по статьям, интерактивный граф технологий, избранное и тёмная тема.
- **Аутентификация** — GitHub OAuth с выдачей JWT; секреты хранятся в `backend/.env`.

### 1.2. Требования к AI-инструменту

| Требование | Что это значит для TrendRadar | Приоритет |
|---|---|---|
| **Доступ к локальным файлам и контексту проекта** | Агенту нужно понимать структуру `backend/`, `collector/` и `frontend/`, видеть связи между файлами, учитывать `AGENTS.md` и не ломать существующие API-контракты | Высокий |
| **Безопасность данных** | Код, JWT-секреты, GitHub OAuth credentials и данные MongoDB не должны уходить во внешние сервисы без необходимости; нужна возможность работать с локальной моделью | Высокий |
| **Нулевой бюджет** | Нельзя оплачивать подписку или API-токены; допустимы локальные модели и бесплатные тарифы | Высокий |
| **Скорость и качество** | Агент должен быстро вносить изменения в несколько файлов и объяснять архитектурные решения | Средний |
| **Кроссплатформенность** | Основная среда — Windows + PowerShell, дополнительно Linux/macOS | Средний |
| **Отсутствие vendor lock-in** | Возможность сменить модель или провайдера без переписывания проекта | Средний |

## 2. Сравнительная таблица инструментов

Оценка по 5-балльной шкале, где **5 — лучший результат**.

| Инструмент | Класс | Контекст | Скорость | Качество | Стоимость | Безопасность | Итог |
|---|---|---:|---:|---:|---:|---:|---|
| **v0.dev** | Cloud-агент для UI | 2 | 5 | 4 | 3 | 2 | Быстро генерирует интерфейсы, но плохо понимает существующий репозиторий и требует выгрузки кода в облако |
| **Bolt.new** | Cloud-агент | 3 | 5 | 4 | 3 | 2 | Удобен для прототипов, но ограничен sandbox-средой и слабо подходит для доработки реального full-stack проекта |
| **Claude Code** | IDE/CLI-агент | 5 | 4 | 5 | 2 | 4 | Сильный анализ контекста и качество кода, но требует подписки/оплаты токенов и отправляет код в облако Anthropic |
| **OpenCode** | Open-source CLI-агент | 5 | 4 | 4 | 5 | 5 | Работает с локальными файлами, поддерживает локальные и бесплатные модели, настраивается под проект и не требует подписки |

### 2.1. Claude Code vs OpenCode

| Критерий | Claude Code | OpenCode |
|---|---|---|
| **Понимание контекста** | Очень высокое: хорошо находит связи между файлами и уверенно рефакторит | Высокое: видит локальные файлы, `AGENTS.md` и историю сессии, но качество зависит от выбранной модели |
| **Модели** | Только модели Anthropic | Любые поддерживаемые провайдеры: Anthropic, OpenAI, OpenRouter, локальные Ollama, LM Studio, vLLM |
| **Стоимость** | Подписка Pro/Max или оплата API по токенам | Бесплатно; можно использовать локальные модели или бесплатные тарифы провайдеров |
| **Лимиты** | Действуют лимиты подписки и/или расход токенов | Ограничены только возможностями выбранной модели и железа |
| **Безопасность** | Код обрабатывается в облаке Anthropic | При локальной модели код не покидает компьютер; при облачной — зависит от выбранного провайдера |
| **Открытость** | Закрытый исходный код | Open-source, можно проверить и расширить |
| **Интеграция с проектом** | Работает через CLI, но сильнее привязан к экосистеме Anthropic | Конфигурируется через `opencode.json`, поддерживает `AGENTS.md`, команды, плагины и MCP |
| **Vendor lock-in** | Высокий | Низкий: модель и провайдера можно сменить в любой момент |

**Вывод по таблице:** cloud-агенты удобны для быстрых прототипов, но не подходят для постоянной работы с реальным репозиторием и чувствительными данными. Claude Code даёт максимальное качество, однако его стоимость и лимиты противоречат условиям студенческого проекта. OpenCode обеспечивает лучший баланс контекста, безопасности, гибкости и нулевой стоимости.

## 3. Обоснование выбора: почему OpenCode

### 3.1. Ограничения Claude Code

Claude Code показал себя как очень сильный инструмент: он хорошо удерживает контекст проекта, аккуратно работает с несколькими файлами и предлагает качественные архитектурные решения. Однако для TrendRadar существенны его ограничения:

- **Платная подписка или оплата по токенам.** Даже при наличии бесплатного пробного периода дальнейшая работа требует регулярных расходов.
- **Лимиты использования.** В активной разработке быстро достигаются ограничения на количество запросов и объём контекста, после чего работу приходится приостанавливать.
- **Закрытость и привязка к одной модели.** Нет возможности выбрать локальную модель или бесплатного провайдера.
- **Облачная обработка кода.** Для проекта с JWT-секретами и GitHub OAuth это создаёт дополнительный риск и требует доверия к внешнему сервису.

### 3.2. Преимущества OpenCode

OpenCode выбран как основной инструмент по следующим причинам:

1. **Open-source и бесплатность.** Нет обязательной подписки; проект можно вести без затрат.
2. **Гибкость моделей.** Один и тот же агент работает с облачными и локальными моделями. Для повседневных задач можно использовать локальную Ollama, а для сложного рефакторинга — более сильную бесплатную модель через `/connect` и `/models`.
3. **Безопасность.** При работе с локальной моделью исходный код и `.env` не отправляются во внешние сервисы. Секреты остаются на машине разработчика.
4. **Понимание проекта.** OpenCode читает локальные файлы, поддерживает `AGENTS.md`, сессии, команды и конфигурацию в репозитории. Это позволяет зафиксировать правила проекта и не повторять их в каждом запросе.
5. **Отсутствие vendor lock-in.** Модель или провайдера можно заменить одной строкой в `opencode.json`, не меняя workflow.
6. **Прозрачность.** Открытый код позволяет проверить, какие данные и как передаются, а также расширить агент плагинами или MCP-серверами.

### 3.3. Итоговое решение

Для TrendRadar выбран **OpenCode** как основной AI-агент. Claude Code остаётся вспомогательным инструментом для отдельных сложных задач, если есть доступ к подписке. Такая схема даёт качество сильной модели там, где оно критично, и нулевые затраты при повседневной разработке.

## 4. Настройка окружения (OpenCode)

### 4.1. Установка

Основной вариант для проекта — установка через npm:

```bash
npm install -g @opencode/cli
opencode --version
```

Альтернативные способы:

```bash
# Linux / macOS: установочный скрипт
curl -fsSL https://opencode.ai/v2/install | bash

# macOS / Linux: Homebrew
brew install anomalyco/tap/opencode-v2
```

Для Windows без npm можно скачать standalone-бинарник `opencode-windows-x64.zip`, распаковать его и добавить папку с `opencode.exe` в `PATH`.

### 4.2. Локальная модель через Ollama

```bash
ollama serve
ollama pull qwen2.5-coder:7b
```

`qwen2.5-coder:7b` — компромисс между качеством генерации кода и требованиями к железу. При нехватке оперативной памяти можно использовать `qwen2.5-coder:1.5b`, а для задач классификации в коллекторе уже применяется лёгкая `qwen2.5:0.5b`.

### 4.3. Конфигурация проекта

В корне репозитория создаётся файл `opencode.json`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "ollama/qwen2.5-coder:7b",
  "providers": {
    "ollama": {
      "settings": {
        "baseURL": "http://127.0.0.1:11434/v1"
      }
    }
  }
}
```

Если Ollama работает на другом хосте или порту, достаточно изменить `baseURL`. Для облачной бесплатной модели вместо блока `ollama` выполняется `/connect` в TUI, затем модель выбирается через `/models`; API-ключ не записывается в репозиторий, а передаётся через переменную окружения.

### 4.4. Запуск и проверка

```bash
cd "C:\Users\1пк\Desktop\2 курс\БД\HackerNews"
opencode
```

В открывшемся TUI:

1. Выполнить `/models` и убедиться, что модель `ollama/qwen2.5-coder:7b` доступна.
2. Проверить, что OpenCode видит `AGENTS.md` и файлы проекта.
3. Для неинтерактивного запуска использовать `opencode run "Кратко опиши архитектуру проекта"`.

### 4.5. Правила безопасной работы

- Секреты хранятся только в `backend/.env`; файл исключён из Git через `.gitignore`.
- В `opencode.json` не должно быть паролей, JWT-секретов и OAuth-ключей.
- Для локальной модели сетевой трафик с кодом не покидает компьютер.
- Перед деструктивными действиями (например, `clean_db.py` или массовое удаление файлов) изменения проверяются вручную.

## 5. Практическое применение

### 5.1. Модуль сбора данных `collector/scheduler.py`

С помощью AI-агентов был создан планировщик сбора данных:

- первичный сбор до 300 статей при старте;
- периодический сбор 50 статей каждые 5 минут через `AsyncIOScheduler`;
- обработка ошибок и логирование этапов сбора;
- корректная остановка планировщика по `Ctrl+C`;
- переиспользование `backend/database.py` через добавление пути в `sys.path`.

Первичный каркас создавался в Claude Code, затем логика была доработана и проверена в OpenCode: добавлены обработка исключений, ограничение параллельных запросов к LLM и защита от повторной обработки уже сохранённых статей.

### 5.2. Компонент графа `frontend/src/pages/Graph.jsx`

В OpenCode был доработан интерактивный граф технологий:

- загрузка данных из `GET /api/graph`;
- построение узлов и связей через `vis-network` и `vis-data`;
- отображение совместных упоминаний технологий (co-occurrence);
- обработка выбора узла и загрузка связанных статей;
- адаптация цветовой палитры и параметров физики графа под тёмную тему.

### 5.3. Документация

С помощью агентов подготовлены Markdown-документы проекта:

- `AGENTS.md` — правила и особенности репозитория для будущих сессий;
- `docs/README.md` — индекс документации;
- `docs/hw1_ai_tools.md` — настоящий отчёт по ДЗ №1.

OpenCode использовался для анализа существующих файлов, формирования структуры документов и проверки соответствия инструкций реальному коду.

### 5.4. Результат перехода на OpenCode

Переход на OpenCode позволил продолжить разработку без ограничений по лимитам подписки и без оплаты токенов. Контекст проекта сохранился благодаря локальным файлам и `AGENTS.md`, а возможность переключаться между локальной и облачной моделями дала гибкость: бесплатная локальная модель — для ежедневных правок, более сильная модель — для сложных задач. Для студенческого проекта с нулевым бюджетом и требованиями к безопасности данных такой выбор является оптимальным.
