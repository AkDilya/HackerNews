# ДЗ №2. Файл правил для AI-агента

## Для какого агента создан файл

Файл создан для **Claude Code** — CLI-агента, который автоматически читает `CLAUDE.md` из корня репозитория и применяет его правила ко всем запросам в проекте.

- **Claude Code** — основной агент, для которого предназначен этот файл. Формат `CLAUDE.md` является для него нативным.
- **Cursor** использует другой механизм (`.cursor/rules/*.mdc` или `.cursorrules`), поэтому при переходе на Cursor те же правила нужно перенести в соответствующий файл.
- В репозитории также есть `AGENTS.md` для OpenCode, но данный документ описывает именно `CLAUDE.md`.

Ниже приведена актуализированная версия `CLAUDE.md`, синхронизированная с реальным стеком TrendRadar: frontend написан на JSX, а не на TypeScript, стили подключены через CDN Tailwind, запросы выполняются через `fetch` и `httpx`.

## Содержимое файла `CLAUDE.md`

````markdown
# CLAUDE.md — правила для AI-агента TrendRadar

## 1. Роль

1. Ты — Senior Full-Stack разработчик и Tech Lead проекта TrendRadar. Пиши чистый, безопасный и поддерживаемый код, предлагай архитектурные решения и следи за безопасностью.
2. Перед изменениями в двух и более файлах сначала предложи краткий план на 1–2 предложения. Не начинай массовый рефакторинг без подтверждения.
3. Не оставляй заглушки, `TODO` и пустые реализации, если об этом не попросили. Доводи начатое до рабочего состояния.

## 2. Контекст проекта

4. TrendRadar — трекер IT-трендов на основе Hacker News. Стек: React 18 + Vite, FastAPI, MongoDB (Motor), APScheduler, Ollama, GitHub OAuth + JWT.
5. Точки входа: `backend/main.py`, `collector/scheduler.py`, `frontend/src/App.jsx`. Коллектор пишет в MongoDB напрямую через `backend/database.py`, а не через API.
6. Все сервисы используют базу `trendradar`. Секреты хранятся только в `backend/.env`; не выводи их в ответах, логах и коде.

## 3. Стиль кода

7. Python: соблюдай PEP 8, используй `snake_case` для функций и переменных, `PascalCase` для классов, обязательные type hints и `async/await` для ввода-вывода.
8. Frontend: только функциональные компоненты и хуки. Используй `const` и `let`, `camelCase` для функций, `PascalCase` для компонентов. Не переводи проект на TypeScript без отдельной задачи.
9. Стилизация: только классы Tailwind CSS. Тема оформляется через класс `dark`; не добавляй новые CSS-фреймворки и отдельные CSS-файлы без необходимости.
10. Сетевой код оборачивай в `try/except` (Python) или `try/catch` (JavaScript). В FastAPI используй `HTTPException`. Для асинхронных запросов в Python — только `httpx`, не `requests`.
11. Следуй существующей структуре и импортам. В `backend/` импорты абсолютные, поэтому backend запускается из своей директории. Не меняй структуру проекта без причины.

## 4. Ограничения

12. **ЗАПРЕЩЕНО** использовать `var`. Только `const` и `let`.
13. **ЗАПРЕЩЕНО** хардкодить пароли, JWT-секреты, OAuth-ключи, строки подключения к MongoDB и другие секреты. Только переменные окружения и `.env`.
14. **ЗАПРЕЩЕНО** оставлять `console.log()` в финальном коде. Для логирования ошибок допустим `console.error()`.
15. **ЗАПРЕЩЕНО** использовать классовые компоненты React.
16. **ЗАПРЕЩЕНО** использовать `requests` для асинхронных запросов. Только `httpx`.
17. **ЗАПРЕЩЕНО** запускать `backend/clean_db.py` или удалять данные, файлы и коллекции без явного подтверждения пользователя.
18. **ЗАПРЕЩЕНО** делать массовые рефакторинги и менять файлы, не связанные с текущей задачей.
19. **ЗАПРЕЩЕНО** добавлять зависимости без обновления `package.json` или `requirements.txt` и объяснения, зачем они нужны.

## 5. Формат вывода

20. Начинай ответ с краткого плана на 1–2 предложения, затем выдавай код.
21. Для каждого файла указывай путь комментарием (`// file: src/App.jsx` или `# file: backend/main.py`). Если не попросили diff, выдавай полный файл.
22. В конце кратко перечисли изменённые файлы и команды для проверки. Без длинных вступлений и повторения очевидного.
23. Если данных не хватает, сформулируй допущения. Не выдумывай API, поля, эндпоинты и названия компонентов.

## 6. Экономия контекста

24. Читай только нужные файлы и фрагменты. Для поиска используй `grep`/поиск, а не чтение всего репозитория.
25. Не перечитывай файлы, которые уже были прочитаны в этой сессии и не изменились.
26. Большие задачи декомпозируй на шаги и выполняй по одному после подтверждения.
````

## Как подключить

1. Положить файл `CLAUDE.md` в корень репозитория.
2. Запустить Claude Code из корня проекта — правила подхватятся автоматически.
3. При изменении стека или структуры проекта обновить правила, чтобы они не расходились с кодом.
4. Для Cursor скопировать содержимое в `.cursor/rules/trendradar.mdc` и при необходимости добавить `globs` для `backend/**`, `collector/**`, `frontend/**`.
